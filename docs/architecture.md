# PG System Architecture Design
> 상세 아키텍처 설계 — CLAUDE.md에서 참조

## 네트워크 4계층 분리

```
┌─────────────────────────────────────────────────────┐
│  INTERNET                                           │
└────────────────────┬────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────┐
│  Layer 1: DMZ (공개 영역)                           │
│  ├─ 웹 서버 (Nginx/CloudFront)                      │
│  ├─ WAF (웹 방화벽)                                 │
│  └─ Rate Limiter                                    │
│  역할: 외부 트래픽 필터링, SSL 종료                  │
│  비유: 건물 정문 경비실                              │
└────────────────────┬────────────────────────────────┘
                     │ (허용된 트래픽만 통과)
┌────────────────────▼────────────────────────────────┐
│  Layer 2: Application Zone (앱 서버)                │
│  ├─ API 서버 (NestJS)                               │
│  ├─ 정산 서버 (배치 처리)                            │
│  ├─ 알림 서버 (이메일/SMS)                           │
│  └─ 큐 서버 (Redis/RabbitMQ)                        │
│  역할: 비즈니스 로직 처리                            │
│  비유: 업무 사무실                                   │
└────────────────────┬────────────────────────────────┘
                     │ (인증된 요청만 통과)
┌────────────────────▼────────────────────────────────┐
│  Layer 3: Data Zone (가장 높은 보안)                 │
│  ├─ PostgreSQL (마스터/레플리카)                     │
│  ├─ 토큰 서버 (카드번호 토큰화)                      │
│  ├─ KMS/Vault (시크릿 관리)                          │
│  └─ 백업 서버                                       │
│  역할: 데이터 저장 및 암호화                         │
│  비유: 은행 금고                                     │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Layer 4: Management Zone (VPN + MFA 필수)          │
│  ├─ 관리자 콘솔 (내부 전용)                          │
│  ├─ 모니터링 대시보드 (ELK/Grafana)                  │
│  └─ CI/CD 파이프라인                                 │
│  역할: 시스템 관리, 접근: VPN + MFA만                │
│  비유: 금고 관리자 사무실 (별도 출입증 필요)         │
└─────────────────────────────────────────────────────┘
```

## 3대 모듈 구조

### 관리자(Admin) 모듈
| 기능 | 설명 |
|------|------|
| 가맹점 관리 | 가맹점 등록/수정/해지, 심사 |
| 대리점 관리 | 대리점 등록/수정, 수수료율 설정 |
| 정산 관리 | 정산 실행/확인, 정산 오류 처리 |
| 수수료 관리 | 수수료율 설정, 수수료 정책 관리 |
| 거래 모니터링 | 실시간 거래 현황, 이상 거래 감지 |
| 시스템 설정 | 운영자 계정, 권한 관리, 로그 조회 |
| 보안 관리 | 접근 로그, 보안 이벤트, IP 화이트리스트 |

### 가맹점(Merchant) 모듈
| 기능 | 설명 |
|------|------|
| 대시보드 | 매출 현황, 거래 통계 |
| 거래 조회 | 거래 내역, 상세 조회, 검색/필터 |
| 정산 조회 | 정산 내역, 정산 예정 금액 |
| 수수료 조회 | 적용 수수료율, 수수료 내역 |
| 가맹점 정보 | 사업자 정보, 계좌 정보 수정 |
| API 연동 | API 키 발급, 연동 가이드, 테스트 |

### 대리점(Agency) 모듈
| 기능 | 설명 |
|------|------|
| 하위 가맹점 관리 | 소속 가맹점 목록, 실적 |
| 수수료 조회 | 대리점 수수료율, 정산 내역 |
| 영업 관리 | 가맹점 모집 현황 |
| 정산 조회 | 대리점 정산 내역 |

## 핵심 데이터 흐름

### 결제 흐름
```
고객 → [가맹점 결제 페이지] → [PG API 서버] → [카드사/은행 API]
                                     ↓
                              [토큰화 서버]  (카드번호→토큰 변환)
                                     ↓
                              [거래 기록 DB] (토큰으로만 저장)
                                     ↓
                              [응답 → 가맹점] (승인번호 반환)
```

### 정산 흐름
```
[매일/주간 배치] → [거래 집계] → [수수료 계산] → [정산 금액 산출]
                                                       ↓
                                               [정산 실행 (이체)]
                                                       ↓
                                               [정산 완료 기록]
                                                       ↓
                                               [가맹점/대리점 알림]
```

### 금액 검증 3단계
```
1단계: 프론트엔드 검증 (사용자 입력 시점)
2단계: 백엔드 검증 (API 수신 시점 — 서명 검증)
3단계: DB 트리거 검증 (저장 시점 — 금액 범위/무결성)
```

## 인증 흐름

```
로그인 요청 → [ID/PW 검증] → [MFA 코드 입력] → [JWT 발급]
                                                    ↓
                                             Access Token (15분)
                                             Refresh Token (7일, HttpOnly)
                                                    ↓
API 요청 → [JWT 검증] → [권한 확인] → [요청 처리] → [접근 로그 기록]
```

### 권한 계층
```
SuperAdmin > Admin > Manager > Viewer (관리자 모듈)
MerchantOwner > MerchantStaff (가맹점 모듈)
AgencyOwner > AgencyStaff (대리점 모듈)
```

## DB 테이블 그룹 (예상)

| 그룹 | 테이블 예시 | 암호화 필요 |
|------|-----------|-----------|
| 사용자 | users, roles, permissions, sessions | ✅ 비밀번호 해시 |
| 가맹점 | merchants, merchant_contracts, merchant_accounts | ✅ 계좌정보 |
| 대리점 | agencies, agency_contracts | ✅ 계좌정보 |
| 거래 | transactions, transaction_logs | ✅ 토큰화된 카드 |
| 정산 | settlements, settlement_details | ✅ 금액 |
| 수수료 | fee_policies, fee_rates | ❌ |
| 시스템 | audit_logs, system_configs, notifications | ❌ |

## 기술 선택 근거

| 결정 | 선택 | 왜? (대안 대비) |
|------|------|----------------|
| 프론트 | Next.js 15 | 서버 컴포넌트로 민감 데이터 서버에서만 처리. React SPA는 클라이언트 노출 위험 |
| 백엔드 | NestJS | Guard/Interceptor 패턴으로 보안 미들웨어 구조화. Express는 자유로워서 빠뜨리기 쉬움 |
| DB | PostgreSQL 전용 | RLS(Row Level Security) 지원. MySQL보다 보안 기능 풍부. Supabase 공유 인프라 금지 |
| ORM | Prisma 또는 TypeORM | Raw SQL 방지 → SQL 인젝션 근본 차단 |
| 큐 | Redis + BullMQ | 정산 배치, 알림 등 비동기 처리. DB 부하 분산 |
